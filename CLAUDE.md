# Health and Fitness for Mac: working rules

Native macOS app (SwiftUI, macOS 14+) with WidgetKit widgets for half marathon
training. The project file is generated by XcodeGen from `project.yml`; never commit the
`.xcodeproj`.

## Process (required for every change, new or update)

Follow `CONTRIBUTING.md`. In short:

1. **Plan**: open a GitHub issue from a template with the goal, scope, acceptance criteria and test plan.
2. **Stage**: branch from `main` as `feature/<issue#>-<slug>`, `fix/<issue#>-<slug>` or `chore/<slug>`.
3. **Develop**: small commits, Conventional Commit messages (`feat:`, `fix:`, `test:`, `docs:`, `chore:`).
4. **Test**: open a draft PR (template filled in). CI must pass: Build and test (macOS) + Content QA.
5. **Error correction**: read the CI logs, fix, push. Repeat 4–5 until green.
6. **QA review**: a separate review pass against `docs/QA_CHECKLIST.md`, recorded as a PR comment. Fix findings, re-run CI.
7. **Release**: mark ready, squash-merge to `main`, update `CHANGELOG.md`, bump `MARKETING_VERSION`, tag `vX.Y.Z`.

Never push straight to `main` except the initial scaffold. Never skip or disable a test to get green.

## Rules for the code

- Strava is read only. Credentials (Strava client ID/secret, tokens, athletedata key) live only in the
  user's keychain, entered by the user in Settings. Never commit or log them.
- Every recovery exercise and running rule must cite a real PubMed source (PMID + DOI) in
  `App/Resources/recovery_library.json`; media links only from trusted hosts (see `scripts/qa_library.py`).
- New PubMed papers found by the weekly check are shown to the user, but the exercise library only
  changes through a reviewed PR.
- Units: miles and min/mile; °F and mph.
